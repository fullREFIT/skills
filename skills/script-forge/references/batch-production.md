# Script Forge Batch Production

Use this when Script Forge is asked to produce packages for multiple ideas at once.

## Batch workflow

1. Load the source idea file and the governing content docs before writing.
2. Produce artifacts as files in the requested or existing batch folder. Do not paste long scripts into chat unless explicitly asked.
3. For each idea, create at least:
   - one long-form YouTube script
   - one short-form script
   - one LinkedIn post
4. If the long-form script is meant for recording, add a recording checklist even when not explicitly asked. Production workflows often expect this file.
5. Write a short run report at the batch root that lists all created files, verification results, and any stats added with sources.
6. If only part of a larger backlog is produced, do not imply the whole backlog is done.

## Verification pattern

After writing the files, run a mechanical scan across the created deliverables before reporting complete:

- file exists
- zero em dashes
- zero semicolons
- zero exclamation marks
- zero `[FILL]` placeholders in finished content
- zero Tier 1 banned-word hits
- LinkedIn posts stay in the target range when a range was specified

If the scan finds issues, patch the files and run the scan again.

## Parallel production pattern

For four or more independent ideas, parallelize drafting by idea if tools allow it, but the parent session must verify the final files directly. Subagent summaries are not enough. The parent owns final QA and the run report.

## Editorial discipline reminder

Every batch still starts with the editorial gate. The creator is the teacher, diagnostician, or operator. Do not turn private working patterns into published content. If an idea only works with the creator as the failure case, reframe it or mark it as a kill candidate.
